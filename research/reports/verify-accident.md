# Verification: verify:accident

Overall reliability: Moderately high. Most numbers hold up on independent checks: ACCIDENT dataset stats, the 2608.08867 and 2605.01512 results, HF model sizes and Qwen licences, TAD, CADP, Nexar, X3D FLOPs, VideoMAEv2 accuracies, the Lipton F1*/2 rule, the 100-Car thresholds, the T4 Gemma TTFT, and the SG noise and IoU calculations (re-run in scratchpad verify_sg.py and verify_iou.py). The recommended architecture fits the spec: trajectory-based boundaries, a learned crop verifier, and a VLM only as an optional ablation. Several details are wrong or outdated. TUM Accid3nD is CC BY-NC-SA, not CC BY. The VideoMAEv2 distilled weights are Apache-2.0, not CC-BY-NC. Qwen3.5-2B defaults to non-thinking. The CAIT study used PET 1.5 s and never mentions DST 3 m/s². ACCIDENT uses the median, not the mean. The frame-difference 0.25 score is misattributed. The vLLM Turing limitation has likely been fixed in v0.30. AI City data no longer needs a request form. There are two substantive logic errors. The claim that near_miss 'cannot dilute' Score_A ignores the spec rule that a predicted-but-absent class joins C with F1 = 0. The accident END formula does not match the spec when involved objects end in mixed ways (one stops, one leaves). Use the report as a design guide, but fix those two points and the licence entries before relying on it.

## Spec / logic errors
- Section 1.1, class-presence logic is wrong. The report says 'Both classes are almost certainly in C ... its ignore rule refers to near_miss GT. So an absent class cannot dilute the score here'. Part B's near_miss ignore rule is a generic metric definition and says nothing about whether near_miss is in the hidden test set. The spec says 'Only classes that occur in the test set or in your predictions enter Score A' and 'A class you predict that never occurs scores 0 for that class and IS ADDED TO C'. One false-positive near_miss on a test set without near-misses costs a full class, since Score_A shrinks by |C|/(|C|+1). Example: 9 present classes at mean F1 0.40 gives Score_A 0.400; a spurious near_miss drops it to 0.360. If near_miss is present, emitting at F1 = 0.25 gains only 0.025. So emit near_miss only if P(near_miss in test) > ~0.6. The same applies to accident, though Part B's existence makes accidents likely. The 'p_match > F1*/2' rule ignores this cost.
- Stage 5 accident END formula, 'min(all involved v<0.5 m/s sustained 1 s, last involved leaves frame)', does not follow the spec convention 'End: all involved objects stop moving or leave the frame'. With one object stopped and the other driving out, neither condition ever fires. The correct form is END = max over involved objects i of min(t_stop_i, t_exit_i), where t_stop_i is the onset of a sustained stop; the 1 s is only a confirmation window. Also clip to duration, since the spec says 'When an event runs past end of video, end_sec = video duration'.
- Section 1.2, 'VLM-grade timing (MAE 1-2 s) limits a 3 s event to about 50-65% expected matching' is too optimistic. MAE 1-2 s corresponds to sigma of about 1.25-2.5 s, and the report's own model then gives about 0.58 to 0.29. The table values quoted (0.67 at sigma 1.0, 0.50 at 1.5) are the sigma/2-padded figures, not the unpadded ones (0.64, 0.45).
- Section 3a cons: the frame-difference z-score result (0.25) is misattributed as 'the published pixel-only zero-shot baseline'. It is a participant's combined time+space+class score, so it cannot support a claim about temporal detection quality.
- Section 1.3 says ACCIDENT START is the 'mean of 3-5 annotators'. The paper uses the median.
- Operating-point rule (Section 5): Score_A = mean over tau in {0.3, 0.5, 0.7} of pooled F1, and F1* and p_match both depend on tau. A single 'p_match > F1*/2' needs a tau-averaged form, e.g. emit if the sum over tau of w_tau*(p_tau - F1*_tau/2) > 0. Otherwise the 0.7 threshold, where F1* is lowest, dominates without anyone noticing. Lipton's result is per class and per tau.
- Section 7, 'TTC risk spikes on real near-misses cost nothing' holds only in part. Ignoring applies to frames in [s_nm - 5 s, e_nm], so a risk rise that starts earlier than 5 s before the evasive-action onset is a counted false alarm. Runs less than 2 s apart are merged, so if an accident follows a near-miss closely, the merged alarm starts inside ignored frames and is discarded, and the accident loses its alarm.
- Section 1.1 describes Score_A as 'a macro average over the classes present in the test set'. The spec's C also includes every class you predict.


## Missing points
- An expected-value policy for whether to emit near_miss (and other rare classes) at all, given the class-dilution rule: set a minimum confidence per class, and consider not predicting near_miss unless its precision on the dev set is high.
- Dependency and runtime risk for the 'Runs as submitted 40%' rubric. PyTorchVideo was last released in Jan 2022, and torch.hub loads need internet, which evaluation lacks. Vendor the X3D definition and ship the .pth. The local machine runs Python 3.14 while the target is 3.10+, so pin versions and test on a clean Python 3.10/3.11 Docker or Kaggle image.
- Local hardware: the GTX 1650 (4 GB) cannot hold Qwen3-VL-2B in fp16 (4.26 GB of weights alone), so VLM ablations and T4-realistic timing must run on Kaggle or Colab T4. A Kaggle T4 matches the evaluation GPU, which suits time-budget measurement.
- Check whether the ACCIDENT real-clip labels are now public, since the paper says per-clip annotations are released. If they are, they give 2,027 median-of-annotators impact times for tuning START without relabelling. END would still need self-annotation.
- Licence corrections for the README: TUM Accid3nD is CC BY-NC-SA 4.0; the VideoMAEv2 distilled checkpoints are Apache-2.0; and several datasets (TAD, TU-DAT, TADS, IITH, AI City) have unstated terms and should be listed as such.
- Using real trajectory datasets (e.g. inD/rounD/INTERACTION, non-commercial) to calibrate TTC/PET/deceleration distributions of normal traffic for near-miss thresholds, since no labelled roadside near-miss set was confirmed.
- Advice that depends on the unknown scene. For a low camera angle or far-field view, footprint gaps from box bottoms become unreliable and should be down-weighted in favour of mask contact and kinematic shock. At night, headlight blobs break the detector and a separate threshold set is needed. If camera.md says the scene is a straight road with no intersection, PET-based crossing conflicts matter less than rear-end TTC.
- Edge cases in the boundary conventions: an accident already in progress at frame 0 (start = 0.0), and involved objects that become occluded rather than leaving the frame.
- Keeping the causal risk curve used as a Part A feature within budget: recomputing Part B inside detect_events roughly doubles that cost, and the time budget in Section 5 does not count it.
- Evidence from the ACCIDENT 1st-place solution (Qwen3-VL-32B-FP8 + 235B MoE on RTX PRO 6000s, ~0.555): even heavy VLMs plateau there, which strengthens the case against a runtime VLM on a T4.
