Traffic events from one fixed camera, found on tracks

We detect every road user in the video, follow each one through time, and read the events off their trajectories: a car that stops in a moving lane, a pedestrian on the carriageway, a vehicle against the flow, a jam, a collision. A second, strictly causal model estimates the chance that an accident starts in the next five seconds.

Live demo

Upload a road video, get the events

The demo runs the same code as our submission. It returns each event as a time segment with a class, an annotated playback with every tracked road user, and the causal accident-risk curve.

What to upload

An .mp4 or .mov from a fixed camera, H.264 or HEVC, up to 2.5 GB. 4K 10-bit 4:2:2 files like the competition samples work. The first 2 minutes are analysed.

How long it takes

The demo server has no GPU, so it runs a smaller detector at 5 frames per second. Expect one to two times the clip length. Progress is shown while it runs.

What you get back

Annotated video, event timeline, risk curve, a table of events and events.json in the competition format.

Exploratory data analysis

The scene, measured by the pipeline

Everything below is computed from our own detections and tracks on the sample videos: how much traffic there is, how fast it moves, where people walk and which way each lane flows. Speeds are in box sizes per second (BS/s), a unit that does not depend on distance from the camera; for a car, 1 BS/s is about 9 km/h.

Approach

Detector, tracker, rules on trajectories

There is one camera and a few hundred minutes of test video, and a predicted class that never occurs costs as much as missing a real one. We chose components we can check frame by frame: a pretrained detector, our own tracker, and one readable rule per event class, tuned on our labels of the samples.

Part A
Decodeone CPU pass, ffmpeg scales 4K to 1280 px, ~10 fps
DetectYOLO26m, COCO weights, 4 groups: vehicle, two-wheeler, person, animal
Trackown ByteTrack: two-stage IoU matching, lifetimes in seconds
Repaircut ID switches, stitch occluded parked cars, speed in BS/s
Sceneroad mask and lane directions learned from moving cars
Rulesone module per class
Segmentsmerge gaps, drop blips, clip to video
Part B
Framesonly those already received, never the future
DetectYOLO26n at 640 px, ~10 fps
Tracksame tracker, own instance
Time to collisionevery pair near a vehicle, footprints extrapolated
Risk< 0.5 ranks conflicts; ≥ 0.5 raises an alarm of at most 8 s

Event classes

Staying inside the time limit

A video that runs over three times its length scores zero for both parts. The harness itself reads every 4K frame for Part B, so before starting Part A we time a few of those reads on the current machine (h, in video lengths) and give Part A what is left:

TA = (3 − 1.25·h − 0.25) × duration

Part A checks the clock before every batch and stops early rather than overrun. Part B projects its finish time every 32 frames and switches itself off if it would miss the limit.

Which classes we predict

Score A averages F1 over every class that appears in the ground truth or in our predictions. A class we predict that is not in the test set adds a zero to the average, however few false alarms it has. We only switch a class on when its rule gives no false alarms on all four samples. The other classes need information a box tracker does not have reliably (traffic-light state, lane markings, smoke) and are left off.
